# 剪切板功能执行计划

## 目标

基于现有 Electron + Vue 前端与 FastAPI 后端，按可交付增量实现剪切板历史管理能力。第一阶段优先交付一个可运行的 MVP：用户可以在应用内查看、搜索、筛选、收藏、置顶、删除剪切板记录，并手动导入当前系统文本剪切板。

## 当前代码接入点

- 前端主入口：`src/App.vue`
- 页面切换与壳层状态：`src/stores/app.js`
- 侧边栏导航：`src/components/layout/Sidebar.vue`
- Electron 桌面桥接：`electron/main.js`、`electron/preload.js`、`src/composables/useElectron.js`
- 后端 API 汇总入口：`app/main.py`
- 现有 JSON 存储范式参考：`app/records/manager.py`

## 分阶段执行

### 第一阶段：MVP 骨架与最小可用链路

目标：
- 新增剪切板页面并挂入主导航
- 后端支持剪切板条目增删改查、搜索、筛选、统计
- Electron 支持读取当前系统文本剪切板
- 前端支持手动导入文本、收藏、置顶、删除、复制

交付物：
- `app/clipboard/` 模块
- `/api/clipboard/*` 接口
- `src/components/clipboard/ClipboardPage.vue`
- `src/composables/useClipboard.js`
- Electron `readClipboardText` 桥接

验收标准：
- 应用中可切换到“剪切板”页面
- 点击“导入当前剪切板”可新增一条文本记录
- 搜索、类型筛选、收藏、置顶、删除可正常工作
- 页面样式与设计稿主色调、层次、卡片结构保持一致

### 第二阶段：内容识别与详情体验

目标：
- 完善内容分类：文本、长文本/代码、链接、文件路径
- 增加详情视图或详情抽屉
- 丰富操作：复制路径、快速访问链接、编辑文本内容

交付物：
- 类型检测增强
- 详情组件
- 条目编辑接口和前端交互

验收标准：
- 同一页面可区分并正确渲染不同内容类型
- 链接、文件路径、长文本在卡片和详情中有差异化展示

### 第三阶段：系统集成

目标：
- 自动监听系统剪切板变化
- 去重与节流，避免高频重复写入
- 与托盘、WebSocket、悬浮窗联动

交付物：
- 桌面端监听器
- 后端或 Electron 事件同步
- 悬浮窗口入口与最近记录列表

验收标准：
- 复制文本后可自动入库
- 托盘或快捷入口可以快速打开最近剪切板记录

### 第四阶段：安全与可靠性

目标：
- 落地本地加密存储策略
- 控制历史容量与清理策略
- 补齐测试与异常恢复

交付物：
- 加密存储方案
- 容量上限与清理任务
- 单元测试与集成测试

验收标准：
- 历史记录有上限且不会无限增长
- 敏感数据具备基础存储保护
- 核心管理逻辑有自动化测试覆盖

## 第一阶段拆解

1. 后端
- 新增 `ClipboardItem` 模型与 `ClipboardManager`
- 按 JSON 文件持久化，目录独立于录音记录
- 提供列表、详情、新建、更新、删除、统计接口

2. Electron
- 新增读取当前文本剪切板 IPC
- 复用现有写入剪切板能力

3. 前端
- 新增剪切板页面与导航入口
- 新增剪切板 composable
- 用设计稿风格实现头部、筛选栏、卡片网格、空状态

4. 验证
- Python 侧管理器基础验证
- 前端构建验证

## 风险与取舍

- 本阶段只处理文本输入链路，图像与文件内容先不接系统监听。
- 先做手动导入而不是自动监听，是为了避免把桌面监听、去重、跨平台兼容一次性绑死在首批改动里。
- 详情页和悬浮窗先不进入首批实现，否则会显著扩大 UI 与 Electron 侧范围。
