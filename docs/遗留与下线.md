# 遗留与下线

> 当前架构见 [架构.md](架构.md)。本文是**可执行清单**：还差哪些能力、旧代码怎么删干净、新机器要准备什么。

## 1. 迁移与下线状态

Electron + Python 的全部运行能力都已在 Rust 侧重建：录音采集与编排、豆包/ChatGPT/本地 Whisper/本地 Qwen 识别、
LLM 优化、文件转写与校对、记录库、剪贴板历史与悬浮框、托盘、全局热键、粘贴与静音、设置与数据迁移。

旧栈代码已于 **2026-11-01 全部从仓库删除**（见 §2 留档），运行时只依赖 Tauri 2 + Rust + Vue 3，不依赖 Python / Node。

## 3. 已知限制

| # | 限制 | 现状 / 影响 |
| --- | --- | --- |
| 1 | **CUDA 未验证** | `att-whisper` 有 `cuda` 特性（`ct2rs/cuda` + `cudnn`），但开发机缺 cuDNN SDK，GPU 路径没实编译验证；CPU 下 large-v3 约 1.5 倍音频时长，实时录音够用、长文件偏慢 |
| 2 | **sherpa-onnx 动态库未接入打包** | 只在开发态从 `models/sherpa-onnx/` 加载；安装版里 Qwen 会因缺库返回可读错误（Whisper 不受影响） |
| 3 | **Qwen 无流式** | ONNX 导出版没有流式接口；`recording_mode=streaming` 只支持豆包，其余引擎给出可读提示 |
| 4 | **Qwen 为 0.6B int8** | 旧 Python 版默认 1.7B；`qwen_asr_device` / `dtype` / `use_forced_aligner` 等设置项当前不生效（ONNX CPU、无强制对齐），设置页字段保留但会被忽略 |
| 5 | **无语言概率** | CTranslate2 不返回 `language_probability`；Qwen 语言由模型自判（sherpa 配置无语言参数） |
| 6 | **本地引擎首载 5~15 秒** | 懒加载，之后常驻；冷启动预热会被 `/api/model-service/start` 触发 |
| 7 | **网页模式与多段会话端点返回 501** | `/api/audio/upload`、`/api/sessions*` 只服务旧浏览器录音路径，Tauri 版录音全在 Rust Actor 内完成 |
| 8 | **数据维护 CLI 已随旧栈删除** | `housekeeping.py`（孤儿清理 / 卡死状态收敛）随 Python 一起删除，Rust 侧没有等价命令；启动期只做迁移，不做体检。需要时从 git 历史取回脚本行为再移植 |
| 9 | **改名「落墨」后旧版不自动卸载** | 2.2.0 起 `productName` 由 `Audio to Text` 改为 `落墨`：NSIS 按新名装到新目录，旧版需在「应用和功能」里手动卸载；MSI 的 `upgradeCode` 按旧名固定，会直接升级替换。macOS 旧 `Audio to Text.app` 需手动删，新 `落墨.app` 要重新授予「输入监控 / 辅助功能 / 麦克风」。数据目录按 identifier 不变，记录与设置都在 |
| 10 | **识别侧热词只有豆包生效**（LLM 纠错不受引擎限制） | faster-whisper（ct2rs 高层接口不支持前置提示，要改用底层接口自拼 `<\|startofprev\|>` 提示）、Qwen3-ASR（sherpa-onnx 无此配置）、ChatGPT 听写（接口只收音频）都不支持；豆包双向流式只认约 100 tokens（约 25~30 个词） |
| 11 | **检查更新只下载、不自动安装** | 更新源是 GitHub `BUGLAN/att` 的 `releases/latest`（仓库已公开，匿名可读）；检查到新版本后只把安装包下载到 `data/updates/`，由用户自己打开安装，未接 `tauri-plugin-updater`（需要更新签名密钥与 `latest.json`，见待办）。macOS 发布目前只有 aarch64 包，Intel 机器检查到新版本也不会给下载。GitHub 匿名接口有频率限制（每小时 60 次/IP），触发时「关于」页会显示 HTTP 403 原因 |

## 4. 待办（按优先级）

1. **打包 sherpa-onnx 动态库**（`sherpa-onnx-c-api.dll` / `onnxruntime.dll` 落到 exe 同目录），否则安装版 Qwen 不可用；
2. **CUDA 路径实编译验证**（装 cuDNN SDK 后跑 `--features cuda` 的真机用例）；
3. **数据维护命令**：至少把「启动时把卡在 `optimizing` 的记录复位为 `transcribed`」补上（崩溃恢复），再加一个
   只读体检 + 显式清理的诊断入口，保留「默认只读、目录包含性校验、隔离不删除」三条安全约定；
4. （可选）Qwen 换 1.7B ONNX 导出版，或补 `language_probability` 的替代字段；
5. （可选）应用内一键安装更新：接 `tauri-plugin-updater`，`release.yml` 打开 `createUpdaterArtifacts` 并配置
   `TAURI_SIGNING_PRIVATE_KEY`，产出签名包与 `latest.json`（见已知限制 #11）；
6. （可选）CI 增加 Rust 测试 job：`cargo test --workspace` 需要 CMake + CTranslate2 编译，托管 runner 上约 20–40 分钟，
   目前只靠本机与 release.yml 的打包流程覆盖。

## 5. 新机器准备（模型与推理库不进仓库）

`models/`、`src-tauri/target/` 都在 `.gitignore` 里。路径可用环境变量改（见 [架构.md §11](架构.md#11-环境变量)）。

| 组件 | 位置 | 获取方式 |
| --- | --- | --- |
| faster-whisper（CTranslate2 large-v3，约 2.9GB） | `models/faster_whisper/`（`model.bin`、`tokenizer.json`、`preprocessor_config.json`） | 旧版 Python 已下载过就直接复用；否则 `ct2-transformers-converter --model openai/whisper-large-v3 --output_dir models/faster_whisper --copy_files tokenizer.json preprocessor_config.json` |
| Qwen3-ASR（ONNX int8，约 940MB） | `models/qwen3-asr-0.6B-int8/`（`conv_frontend.onnx`、`encoder.int8.onnx`、`decoder.int8.onnx`、`tokenizer/`） | `wget https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-qwen3-asr-0.6B-int8-2026-03-25.tar.bz2 && tar xvf … -C models/` |
| sherpa-onnx 动态库（v2.0.1） | `models/sherpa-onnx/`（`sherpa-onnx-c-api.dll` + `onnxruntime.dll` 等） | Windows 取 `sherpa-onnx-v2.0.1-win-x64-shared-MD-Release-lib.tar.bz2`，macOS 取 `…-osx-universal2-shared-lib.tar.bz2`，解压 `lib/` 内容即可 |

注意：

1. Windows 上**别**让 `C:\Windows\System32\onnxruntime.dll`（其它软件装的旧版）被解析到。`att-qwen` 的 `shim.c` 已按绝对路径
   预加载推理库同目录的 ORT，但 `models/sherpa-onnx/` 里缺 `onnxruntime.dll` 仍会崩在 API 版本检查上。
2. 首次 `cargo build` 会编译 CTranslate2 + oneDNN（Windows 16 核约 10~20 分钟），之后走缓存。
3. `vendor/c-api.h` 与运行期动态库版本必须一致（同为 v2.0.1），升级库时一起换。

## 6. Windows 实机验收（macOS 上测不了的部分）

| 项 | 方法 |
| --- | --- |
| 修饰键不粘滞 | Win+L 锁屏解锁后，单按 Alt / Alt+Tab 不应触发录音；默认 Win+Alt 按住录音正常 |
| 录音静音 | 开启「录音时暂停其他音频」，录音中切换耳机/扬声器，结束后系统静音状态正确恢复 |
| 托盘 | 左键唤起主窗口、右键菜单最近 10 条点击即粘贴、四态图标随录音切换；100% / 125% / 150% / 200% 缩放下「墨 聽 轉 斷」都清楚 |
| 关窗 | 关闭主窗口即退出进程（任务管理器无残留） |
| 自动粘贴 | 粘贴到记事本 / 浏览器输入框 / 微信 |
| 剪贴板图片 | 悬浮框选图片卡片，粘贴到聊天框、微信、Word 都有图（格式问题见 `clipboard_image.rs`） |
| 文件转写 | 未装 ffmpeg 时提示可读；`ATT_FFMPEG_DIR` 指定后可用；转写过程不弹控制台窗口 |
| 优化选中文本 | 记事本 / 浏览器输入框 / VS Code 里选中文字按 `Alt+A`：不弹出菜单栏、不打出字符，悬浮条出现「轉」，结果流式替换选区；没选中时提示「没有读到选中的文字」。`desktop.rs` 的 Windows 分支（模拟 Ctrl+C、`GetClipboardSequenceNumber`）在 macOS 上交叉编译不过 C 依赖，未实编译 |
| 应用图标 | 100% / 125% / 150% / 200% 缩放下看任务栏、开始菜单、资源管理器、Alt+Tab 的「墨」图标都清楚不发糊 |
| 打包 | `npm run tauri:build`：NSIS / MSI 可安装，安装版读到随包 `prompts/`，数据目录落在应用数据目录 |
