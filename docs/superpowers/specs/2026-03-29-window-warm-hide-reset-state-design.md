# 悬浮窗常驻预热与瞬时状态重置设计

## 背景

当前通过“关闭即销毁窗口”的方式，避免了录音悬浮框和剪切板悬浮框在第二次及之后打开时的闪烁/重复打开问题，但副作用很明显：

- 每次打开都要重新创建 `BrowserWindow`
- 每次都要重新加载 renderer 页面
- 开发环境下会明显感知到启动延迟

本次改动目标改为：

- 首次使用时再创建窗口
- 创建后窗口常驻后台
- 关闭时只重置会污染下一次打开的瞬时状态
- 保留上次界面状态
- 不重新引入“第二次以后闪烁/重复打开”的问题

## 目标与非目标

### 目标

- 录音悬浮框采用“首次懒创建 + 常驻隐藏”
- 剪切板悬浮框采用“首次懒创建 + 主窗口常驻隐藏”
- 剪切板悬浮框每次关闭时销毁外围 dismiss/backdrop 窗口
- 保留 renderer 内部界面状态
  - 剪切板悬浮框保留搜索词、选中项、滚动位置
  - 录音悬浮框保留最近一次 renderer 状态，下一次由新状态覆盖
- 保留已加入的输入防重逻辑
  - 热键完全松开后才能重新触发
  - 鼠标中键按下一次只触发一次

### 非目标

- 不修改后端 WebSocket 协议
- 不重写剪切板悬浮框 renderer 组件
- 不改变用户现有快捷键和交互语义

## 方案

### 1. 录音悬浮框

文件：`electron/floatingWindow/index.js`

设计：

- 移除启动阶段的预创建，不再在应用 ready 时提前 `preload()`
- 第一次收到 `show()` 或非 idle 的 `updateState()` 时再创建窗口
- `hide()` 恢复为只隐藏窗口，不销毁窗口实例
- `hide()` 不再清空 renderer 所依赖的界面状态，仅更新可见性标记
- 下一次录音开始时，仍由 `updateState()` 推送新的 recording/transcribing 状态覆盖旧内容

原因：

- 录音悬浮框的重复打开根因主要在输入链路，不在窗口实例本身
- 录音窗口 UI 简单，保留窗口实例不会带来外围焦点管理复杂度

### 2. 剪切板悬浮框

文件：`electron/clipboardOverlay/index.js`

设计：

- 主 overlay 窗口首次使用时创建，之后始终复用同一个主窗口
- `hide()` 只隐藏主窗口，不销毁主窗口
- 每次关闭时，必须销毁本轮创建的 dismiss/backdrop 窗口
- 每次关闭时，必须清空主进程瞬时控制状态：
  - focus guard timers
  - dismiss show timer
  - `dragInProgress`
  - `ignoreBlurUntil`
  - 当前 show 序列对应的一次性焦点保护态
- 每次再次打开时：
  - 复用已有主窗口
  - 重建 dismiss/backdrop 窗口
  - 重新 armed 焦点保护
  - 向 renderer 发送新的 activate 事件，但不强制 renderer 丢弃已有界面状态

原因：

- 剪切板悬浮框的脏状态主要在主进程控制层，而不是 renderer 页面本身
- 真正需要按次重建的是外围 dismiss/backdrop，而不是主窗口
- 这样既能保留搜索词等界面状态，又能切断上一轮焦点/外层窗口残留状态

### 3. 状态边界

保留状态：

- 主窗口实例
- renderer 已加载页面
- renderer 内部 UI 状态
- 剪切板悬浮框的 query、selectedIndex、滚动位置
- 录音悬浮框最近一次展示内容

关闭时重置的瞬时状态：

- dismiss/backdrop 窗口集合
- 焦点守卫定时器
- 拖拽进行中标记
- blur 宽限期
- 本轮 show 序列上的一次性保护态

### 4. 触发链保护

文件：`electron/input/listener.js`

现有输入防重逻辑保留，不回退：

- 热键 stop 后，必须完整松开配置中的按键组合，才能允许下一次 start
- 中键触发改为按下期间只触发一次，抬起后重新 armed

原因：

- 这些逻辑修的是输入层重复事件，不应随窗口生命周期方案回退

## 数据流

### 录音悬浮框

1. 首次录音开始时创建主窗口
2. `updateState()` 发送 recording 状态
3. `show()` 展示窗口
4. 录音结束后 `hide()` 仅隐藏
5. 下一次录音重新 `updateState()` 并展示同一窗口

### 剪切板悬浮框

1. 首次触发时创建主 overlay 窗口
2. 打开时创建本轮 dismiss/backdrop 窗口
3. 关闭时销毁 dismiss/backdrop，隐藏主窗口
4. 再次打开时复用主窗口，只重建外围 dismiss/backdrop

## 错误处理

- blur 事件在窗口已隐藏时应直接忽略，避免隐藏后的残留 blur 再次触发关闭链
- dismiss/backdrop 的 pointer down 只在当前窗口可见时生效
- 若主窗口已销毁，下一次 show 自动走首次创建逻辑

## 测试

新增或更新的验证点：

- 录音悬浮框 `hide()` 后仍保留同一主窗口实例
- 剪切板悬浮框 `hide()` 后仍保留同一主窗口实例
- 剪切板悬浮框 `hide()` 后 dismiss/backdrop 窗口被销毁
- 再次 `show()` 时剪切板悬浮框复用主窗口，但会重新创建 dismiss/backdrop
- 现有桌面输入测试继续通过

## 风险

- 若剪切板悬浮框 renderer 内部也存在脏状态，主进程只重置瞬时状态可能还不够
- 若 `refreshOverlay()` 在 activate 时覆盖过多 renderer 状态，可能会部分抵消“保留界面状态”的目标

## 验收标准

- 第一次打开仍可正常创建窗口
- 第二次及之后打开不再明显变慢
- 第二次及之后打开不再闪烁或像“打开两次”
- 剪切板悬浮框关闭再打开后，搜索词等界面状态仍保留
- 录音悬浮框再次使用时可被新状态正常覆盖
