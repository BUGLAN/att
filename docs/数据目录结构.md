# 数据目录结构（data/）

> 适用范围：Electron + Python 后端的 ATT 桌面应用。
> 关联脚本：`scripts/migrate_data.py`（体检 / 导出 / 布局互转）、`scripts/housekeeping.py`（孤儿清理，独立安全阀）。
> 关联打包配置：`electron-builder.yml`、`electron/python/manager.js`。

---

## 1. 数据目录在哪（开发态 vs 安装态）

**这是最容易踩坑的一点**：打包版的数据目录**不是**安装目录，而是用户目录。

| 运行形态 | 数据目录 | 说明 |
| --- | --- | --- |
| 开发态（`npm run electron:dev` / 直接跑后端） | `<仓库根>/data/` | 用户现有的真实数据就在这里，**任何改动都不得搬动它** |
| 安装态（`app.isPackaged === true`） | `<userData>/data/` | Windows 通常是 `%APPDATA%\Audio to Text\data`；由 Electron 通过环境变量 `DATA_DIR` 注入 |

判定与注入逻辑集中在两处：

- `electron/python/manager.js`
  - `isPackagedRuntime()`：优先看 `app.isPackaged`，为真才是安装态；
  - `getPackagedDataDir()`：只有安装态才返回 `<userData>/data` 并提前 `mkdirSync`；
  - `start()`：仅当该函数返回值非 null 时注入 `DATA_DIR`，开发态**完全不设置**该变量。
- `electron/python/runtime-manager.js`：同一套判定，供桌面 Agent 等辅助进程复用。

后端 `app/config.py` 的 `Settings.data_dir` 默认值是 `"data"`（相对进程工作目录，即 `resources/`），
环境变量 `DATA_DIR` 一旦注入就会覆盖它（pydantic-settings 大小写不敏感，`data_dir` 同样生效）。

**为什么必须这样做**：

1. `data/` 里有 `.encryption_key`（解密 API Key 的密钥）与 495 MB 私人录音，**不能**进安装包；
2. 安装目录（`Program Files`）对普通用户通常不可写，写在那里会直接失败；
3. 卸载安装目录会连带删除数据，用户数据必须放在 `userData` 才安全。

## 2. 目录布局

```text
data/
├── .schema_version              # 数据目录结构版本（单行整数，当前 1）
├── .encryption_key              # API Key 加密密钥（禁止随包/随备份分发）
├── settings.json                # 业务设置（录音模式、默认提示词、开关项…）
├── settings.json.bak-<时间戳>   # 设置自动备份（残留项，可清理）
├── llm_configs.json             # LLM 供应商配置（密钥字段为密文）
├── records/                     # 转写记录：一条记录一个 <record_id>.json
├── sessions/                    # 多段/流式会话：<session_id>.json（内含 segments[]）
├── clipboard/                   # 剪贴板历史
│   ├── <clipboard_id>.json
│   └── images/                  # 图片类条目的落盘图片
├── wordbook/                    # 生词本：<word_id>.json
├── audio/
│   ├── records/                 # 记录/会话音频（默认平铺，可切分片）
│   ├── permanent/               # 导出用的永久音频（少见）
│   └── temp/                    # 转码中间产物（可清理的残留）
└── test-clipboard/              # 开发测试残留目录（可清理）
```

### 2.1 关键文件

| 文件 | 作用 | 缺失后果 |
| --- | --- | --- |
| `.schema_version` | 标记数据目录结构版本，`migrate_data.py` 据此判断是否需要迁移 | 体检报 warning；布局互转时会自动补写 |
| `.encryption_key` | 加解密 `llm_configs.json` 里的 API Key | 已保存的 API Key 无法解密，需要重新填写 |
| `settings.json` | 业务设置持久化 | 后端回落到默认设置 |

### 2.2 记录 JSON 形态（节选）

```json
{
  "id": "0051a09d-80b6-465b-9d80-61a0e57d002f",
  "created_at": "2026-03-29T16:07:34.849651",
  "audio_path": "data\\audio\\records\\8bc705aa-2cab-4594-8de4-3ef9309fbbb8.wav",
  "duration": 7.02,
  "raw_text": "…",
  "optimized_text": "…",
  "status": "optimized"
}
```

会话额外带 `segments[]`（每段一个 `audio_path`）与可选的 `merged_audio_path`。

## 3. `audio_path` 的三种历史写法（务必兼容）

历史代码在不同时期写过三套路径风格，后端与工具都必须全部认：

| 风格 | 示例 | 基准目录 |
| --- | --- | --- |
| 相对仓库根（反斜杠） | `data\audio\records\x.wav` | 进程工作目录（开发态=仓库根） |
| 相对仓库根（正斜杠） | `data/audio/records/x.wav` | 同上 |
| 相对 `data/` | `audio/records/x.wav` | 数据目录 |
| 容器内绝对路径（Docker 版遗留） | `/app/data/audio/records/x.wav` | 宿主机上按文件名回落到 `data/audio/records/` |

`migrate_data.py` 的 `DataStore.resolve_audio()` 按「谁真实存在就用谁」的顺序依次尝试，
全部落空时按「相对 `data/`」返回，从而把「路径写错」与「音频真丢了」区分开。

> ⚠️ **致命陷阱**：平铺布局下 **wav 文件名 ≠ record id**。
> 真实数据实测：758 个 wav 的文件名主干与 709 个 record id **交集为 0**——
> 音频名是另一次 `uuid4()` 生成的。任何脚本都**必须**以 JSON 里的 `audio_path`
> 为准，**禁止**用 `records/<id>.json` 去推导 `audio/records/<id>.wav`。

## 4. 音频目录两种布局：平铺 与 分片

| 布局 | 形态 | 适用 |
| --- | --- | --- |
| **平铺（flat，默认）** | `audio/records/<uuid>.wav` | 当前真实数据；单目录 758 个文件仍可接受 |
| **分片（sharded）** | `audio/records/<前2位>/<次2位>/<uuid>.wav` | 音频数量上万时避免单目录膨胀（部分文件系统单目录数万文件会明显变慢） |

- 互转一律走 `scripts/migrate_data.py`，**不要手写脚本挪文件**（要同步回写 JSON）。
- 转换顺序固定为「移动文件 → 回写 `audio_path`」，且路径写法沿用该条 JSON 原本的风格；
- 未被任何记录引用的孤儿音频同样会被搬运（本工具不删数据）；
- 目标已存在同名文件时**跳过并告警**，不覆盖；
- 执行完立刻复检，出现引用断链时返回非 0 退出码，提示用备份回滚。

```powershell
# 预演（只读，打印将要移动的文件数与体积）
uv run python scripts/migrate_data.py --to-shard
# 真正执行
uv run python scripts/migrate_data.py --to-shard --apply
# 回到默认的平铺布局
uv run python scripts/migrate_data.py --to-flat --apply
```

## 5. 体检（`--check`）

```powershell
uv run python scripts/migrate_data.py --check              # 人类可读
uv run python scripts/migrate_data.py --check --json       # 机器可读
uv run python scripts/migrate_data.py --check --strict     # 有 error 时退出码 1（CI 用）
uv run python scripts/migrate_data.py --data-dir D:\x\data # 指定数据目录（默认 $env:DATA_DIR，再退回仓库 data/）
```

体检覆盖：

1. **全量 JSON 可解析**：`records/`、`sessions/`、`clipboard/`、`wordbook/` 与顶层散装 JSON 全部解析一遍；
2. **记录数与音频引用可达**：每条记录的 `audio_path` 按四种风格解析后是否真的存在；
3. **孤儿 / 残留统计**：未被引用的 wav、剪贴板孤儿图片、`audio/temp` 残留、备份文件、测试目录、卡在中间态的会话。

### 5.1 已知异常基线（2026-10-01 真实数据实测）

| 指标 | 实测 | 说明 |
| --- | --- | --- |
| 记录 JSON | 709 | — |
| `audio_path == ""` | **36** | 转写失败/上传中断留下的空引用，前端点开会 404 |
| wav 名 vs record id 交集 | **0** | 完全错位，见 §3 的陷阱说明 |
| 音频文件 | 758（459.7 MB） | 其中 86 个未被任何记录引用（约 19.3 MB） |
| 容器内绝对路径引用 | 7 | Docker 版写入的 `/app/data/...`，宿主机靠文件名兜底 |
| 引用不可达 | 1 | `records/24264064-….json` 指向 `test/path.wav`（测试脏数据） |
| 会话 | 44 | 4 个卡在 `recording` 中间态 |
| 剪贴板 | 366 条 / 58 张图 | 41 张图为孤儿 |
| 损坏 JSON | **0** | 健康 |

体检脚本会把这些数字一并打印出来，**0 个损坏 JSON** 与 **交集 0** 是当前数据的两个确定性结论。

## 6. 导出与迁移（换机 / 备份）

```powershell
uv run python scripts/migrate_data.py --export D:\backup\att-data-20261001.zip
```

- 压缩包内是 `data/…` 的完整结构，**解压即用**；
- 默认**排除 `.encryption_key`**（把密钥与密文放进同一个压缩包，等于把 API Key 一起送出去）；
  确实需要连密钥一起备份时显式加 `--include-encryption-key`；
- 包内附带 `data/export-manifest.json`（导出时间、文件数、被排除项、目标目录提示）；
- `*.tmp`、`__pycache__` 等中间产物不进包。

**恢复到另一台机器**：

| 目标形态 | 放置位置 |
| --- | --- |
| 开发态 | `<仓库根>/data/`（覆盖前先备份） |
| 安装态 | `%APPDATA%\Audio to Text\data\`（或 `DATA_DIR` 指向的目录） |

放置完成后跑一次 `--check` 确认引用可达。

## 7. 打包相关红线

`electron-builder.yml` 的 `extraResources` **只允许**包含：

- `python-dist/` → `resources/python/`（解释器与依赖）
- `app/**/*.py` → `resources/app/`（后端源码）
- `prompts/**/*.txt` → `resources/prompts/`（提示词预设）

**禁止**包含：

- `data/`：495 MB 私人录音 + `.encryption_key`（密钥与密文同包 = API Key 明文泄漏）；
- `models/`：10.24 GB 模型权重，体积不可接受，应在首次运行时下载到 `models/`。

`prompts/` **必须**包含：`app/prompts/file_manager.py` 按 `<repo|resources>/prompts` 定位预设，
漏掉这一项会让打包版出现「零个提示词预设」，LLM 优化直接失效。

安装后自检（一步确认打包结果是否干净）：

```powershell
# 在 release/win-unpacked 下执行：应列出 data/models 不存在、prompts 存在
Test-Path resources\data; Test-Path resources\models; (Get-ChildItem resources\prompts -Filter *.txt).Count
```

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 安装版启动后记录全空 | 启动的是安装态，数据在 `<userData>/data`，而旧数据在仓库 `data/` | 按 §6 迁移数据，或确认 `DATA_DIR` 指向 |
| 开发态数据「消失」 | 误把数据目录切到 `userData` | 检查 `app.isPackaged` 与 `NODE_ENV`；开发态**不该**出现 `DATA_DIR` |
| 提示词预设为 0 | 打包漏了 `prompts/` | 检查 `extraResources` 与 `resources/prompts` |
| API Key 无法解密 | `.encryption_key` 丢失或换机未带 | 重新在设置里填写 API Key |
| 音频点开 404 | 该记录 `audio_path` 为空（36 条已知）或指向 `test/path.wav` | 属于历史脏数据，可在记录库删除 |
| 单目录文件过多变慢 | 平铺布局堆积 | `--to-shard --apply` 切分片布局 |
