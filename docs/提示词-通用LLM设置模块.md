## 0. 你要做的事（一句话）

在我指定的项目里，新增一个**通用的「LLM 设置」模块**：让用户可以在设置页接入任意大模型服务商、
管理多套凭据与多个模型、随时切换默认模型、当场验证连通性，并且**服务商发布新模型时不需要改代码、不需要发版**。

这不是一个「AI 功能」，而是所有 AI 功能的**底座**。请按底座的标准来做：稳定、可验证、可迁移、不泄漏密钥。

## 2. 这个模块是什么，不是什么

**是什么**：一个「凭据与模型的注册表 + 一个唯一的调用出口」。
用户在这里把「哪家服务商、什么密钥、哪个模型、什么参数」配好，业务代码从这里取到可调用的模型。

**不是什么**（看到这些需求请停下来确认，不要顺手做）：

- 不是聊天界面 / 不是 AI 助手 UI；
- 不是模型能力封装（不做提示词编排、不做 RAG、不做 Agent）；
- 不是计费系统、不是配额系统、不是团队权限系统；
- 不是模型评测 / 对比 / 智能路由平台；
- 不是服务商 SDK 的薄包装集合（那正是要消灭的东西，见 §3）。

## 3. 设计目标：为什么长这样

这一节是**决策依据**。不理解原因就会做出「看起来对、实际腐烂」的实现。

### 3.1 要解决的五个真实痛点

| # | 痛点 | 后果 | 本设计的解法 |
| --- | --- | --- | --- |
| P1 | 模型清单硬编码在代码里 | 服务商每月上新模型，应用里永远选不到，只能改代码发版；清单从写下那天开始腐烂 | 模型名**可手输、可拉取、原样透传**，代码里不存模型清单 |
| P2 | 新增服务商要写代码 | 每家一个适配文件，90% 重复；未收录的 OpenAI 兼容端点全部接不了 | 只登记**协议前缀**和元信息；未收录的走「自定义 OpenAI 兼容」兜底 |
| P3 | 一个配置绑死一个模型 | 同一个 key 想用两个模型要录两遍、存两份密文 | 拆成**两层**：供应商档案（密钥）+ 模型条目（挂靠档案） |
| P4 | 调用无超时 | 网络黑洞时界面转圈十分钟，任务卡死 | 网关**每次请求强制注入**超时与重试 |
| P5 | 配置「全有或全无」 | 一条坏数据让全部配置消失 | **逐条容错加载**，坏条跳过并提示，其余照常 |

### 3.2 三个关键判断（请照做，不要重新发明）

1. **前缀是协议，不是清单。**
   模型串形如 `deepseek/deepseek-flash`：斜杠前决定走哪套协议，斜杠后是**原样透传**给上游的模型名。
   这就是「上游上新模型当天即可用」的技术根据。
2. **两层而不是一层。**
   密钥属于「服务商档案」，模型属于「挂在档案下的条目」。密钥只存一份，模型想加几个加几个。
3. **验证是正常业务结果，不是异常。**
   验证失败返回 `200 + {ok:false, error_code}`，不是 5xx。「密钥错了」和「你的服务挂了」必须能区分。

## 4. 架构

```text
前端设置页
  ├─ 供应商档案列表（状态徽章 + 最近验证延迟）
  └─ 模型表（默认徽章 / 模型串 / 参数摘要 / 逐模型状态）
        │  HTTP
        ▼
后端 API 层（只做解析与组装，不写业务）
        │
        ├──> Store：档案 + 模型持久化（原子写 / 单写者 / 逐条容错）
        └──> Gateway：唯一的调用出口（超时 / 重试 / 错误分级 / 脱敏 / usage）
                │
                ▼
        统一接入层（{{接入层}}）
                │
                ▼
        上游：DeepSeek / OpenAI / Anthropic / Ollama / 任意 OpenAI 兼容端点
```

**硬性分层约束**：

1. API 层**只做**「解析请求 → 调 Store/Gateway → 组装响应」，不写业务规则。
2. **所有**对外模型调用必须经过 Gateway，业务代码不得自己 `new` 客户端。
3. Gateway 是**唯一**注入超时、重试、脱敏、usage 归一化的地方。
4. 前端访问后端只走项目既有的 HTTP 包装层，不在组件里裸写请求。

### 4.1 接入层选型

| 情况 | 做法 |
| --- | --- |
| 生态里有成熟的「一套接口调多家」的库（如 Python 的 LiteLLM） | **优先用它**；锁版本；懒加载（首次 import 有可感开销，别拖慢启动） |
| 没有，或引入成本不可接受 | 实现**最小等价层**：一个 `chat(model_string, messages, key, base)` 函数 + 前缀路由表；<br>必须保持 §5 与 §7 的**对外契约完全不变** |

无论哪种，**不要把服务商协议细节泄漏到业务层**：业务层只知道「有个模型串，能调用，会失败」。

## 5. 数据模型（两层）

落盘为一个文件，带版本号：

```jsonc
{
  "version": 2,

  // 第一层：供应商档案 —— 一家服务商的凭据与端点，密钥只存这一份
  "profiles": [
    {
      "id": "prof-1761043200000",
      "provider": "deepseek",          // 注册表 id（见 §6），决定协议前缀
      "name": "DeepSeek 官方",          // 用户可改的显示名
      "api_key_encrypted": "gAAA…",     // 只存密文；本地服务可为空
      "api_key_hint": "sk-****7f3a",    // 非敏感的尾号提示，用于界面展示
      "api_base": null,                 // null = 用默认端点
      "extra_headers": {},
      "status": {
        "state": "ok",                  // unknown | ok | failed | decrypt_failed
        "checked_at": "2026-10-22T15:30:00",
        "latency_ms": 812,
        "error_code": null,
        "error": null                   // 已脱敏的失败原因，可直接展示
      }
    }
  ],

  // 第二层：模型条目 —— 挂在档案下的可调用模型
  "models": [
    {
      "id": "mdl-1761043200111",
      "profile_id": "prof-1761043200000",
      "model": "deepseek/deepseek-flash",  // 完整模型串，原样透传给接入层
      "display_name": "DeepSeek Flash",    // 空则回退用模型串
      "params": {
        "temperature": 0.3,
        "max_tokens": 4096,
        "timeout_s": 60,                   // 每次请求强制注入
        "retries": 2                       // 每次请求强制注入
      },
      "status": { "state": "ok", "checked_at": "…", "latency_ms": 812, "error_code": null, "error": null }
    }
  ],

  "default_model_id": "mdl-1761043200111",

  // 可选：备用模型。**只有当你真的实现了「默认模型失败后自动切换」才保留这个字段**；
  // 本期不做（§12.6 建议后置）就必须连字段带界面文案一起删掉 —— 见 I7。
  "fallback_model_id": null
}
```

### 5.1 不变量（不可协商）

| 编号 | 不变量 | 违反后果 |
| --- | --- | --- |
| **I1** | 代码里**不得**出现任何服务商的模型清单（硬编码数组、枚举、下拉选项） | 清单立刻开始腐烂，回到 P1 |
| **I2** | 密钥**只存档案级一份**，模型条目**不存**密钥 | 同一 key 多份密文，改一次要改多处 |
| **I3** | 密钥**只以密文落盘**；任何响应体、日志、异常文案、前端全局状态**都不出现明文** | 一次 401 回显就把 key 写进日志并永久泄漏 |
| **I4** | `timeout` 与 `retries` 由网关在**每次请求强制注入**，绝不依赖 SDK 默认值 | 网络黑洞时挂起数分钟（P4） |
| **I5** | 加载**逐条容错**：单条数据损坏只跳过该条并告警，其余照常可用 | 一条坏数据让用户全部配置消失（P5） |
| **I6** | 默认模型删除前必须先改绑（返回冲突错误），不允许出现「默认指向不存在的模型」 | 运行时报「没有可用模型」，用户困惑 |
| **I7** | 数据结构里出现的每个字段，必须有真实读取方；**存了但没人用的字段一律删掉** | 界面文案宣称的行为与实际不符（最典型的信任崩塌） |

> **I7 是这一节最容易违反的一条。** 参考实现就踩过：`fallback_model_id` 只存不切换、
> `extra_query` 只存不注入、设置页却写着「失败自动切换」。宁可删字段，也不要留半截。

### 5.2 加载期自愈（必须实现）

| 情况 | 处理 |
| --- | --- |
| `default_model_id` 指向不存在的模型 | 回落到第一个可用模型，并**回写修正** |
| `fallback_model_id` 指向不存在的模型（若该字段存在） | 置空并回写 |
| 单条档案/模型字段非法 | 跳过该条，把 `profile:<id>` / `model:<id>` 记进 `skipped`，前端顶部提示「N 条配置因数据损坏被跳过」 |
| 密钥密文解不开（换机器/丢密钥文件） | **不要丢弃该条**：标记 `decrypt_failed`，允许用户重填密钥修复 |
| 历史模型串格式不符规范 | 在加载期一次性修正并回写（写清注释，只在加载期做一次） |

### 5.3 持久化纪律

1. **原子写**：写临时文件 + 原子替换。禁止原地截断写（半截 JSON 会让配置静默消失）。
2. **读-改-写串行化**：同一文件用一把可重入锁。
3. 如果项目已有单写者约束（同一数据目录只允许一个写进程），**沿用**，不要为了"容错"绕开它。

## 6. 服务商注册表

一张表，只存**协议前缀 + 元信息**，**绝不存模型清单**：

```jsonc
[
  { "id": "deepseek",  "name": "DeepSeek",   "litellm_prefix": "deepseek",
    "default_base_url": "https://api.deepseek.com",  "requires_key": true,
    "supports_model_listing": true,  "docs_url": "…" },

  { "id": "anthropic", "name": "Anthropic",  "litellm_prefix": "anthropic",
    "default_base_url": "https://api.anthropic.com", "requires_key": true,
    "supports_model_listing": false, "docs_url": "…" },   // 无 OpenAI 兼容 /models → 引导手输

  { "id": "ollama",    "name": "Ollama（本地）", "litellm_prefix": "ollama_chat",
    "default_base_url": "http://127.0.0.1:11434",  "requires_key": false },

  { "id": "custom",    "name": "自定义 OpenAI 兼容", "litellm_prefix": "openai",
    "requires_key": false, "notes": "任何 OpenAI 兼容端点都走这里" }
]
```

**必含字段**：`id`、`name`、`litellm_prefix`（若接入层不是 LiteLLM，改叫 `protocol_prefix`，
含义不变：**决定拼进模型串的那一段**）、`default_base_url`、`requires_key`、`supports_model_listing`。

**可选字段**：`docs_url`（引导去拿密钥）、`notes`（例如"该前缀未收录时自动回退"）、`suggested_models`
（**只用于探测与提示，绝不允许作为下拉选项的唯一来源**）、`openai_compat_base`
（该服务商的 OpenAI 兼容端点；接入层不认识这个前缀时，自动换成 `openai/<裸名>` + 该端点重试一次，见 §7.2）。

### 6.1 模型串组装规则（三条，必须写死并有测试）

1. **`custom` 最先判断**：恒为 `openai/<完整模型 ID>`，且幂等（已是 `openai/` 开头不重复拼）。
   原因：本地网关 / 中转的模型 ID 常自带斜杠（`group/deepseek-v4.1-flash`），
   若原样透传，接入层会把 `group` 当成服务商前缀，报 `LLM Provider NOT provided`。
2. **其余服务商**：已含 `/` 的名字视为完整模型串，**原样透传**；裸名按注册表前缀组装。
3. **`custom` 必须填 `api_base`**，缺失即报错，不允许静默拼一个空端点。

> **前后端必须用同一套组装规则**，并且各有测试。两边规则漂移是最难查的 bug。

## 7. 网关（唯一的调用出口）

### 7.1 一次调用的完整职责

```text
chat(model_string, messages, api_key, api_base, temperature, max_tokens, timeout_s, retries)
  1. 强制注入 timeout / retries（I4）
  2. 调接入层
  3. 失败 → 分类成 error_code + 脱敏文案（§8）
  4. 成功 → 归一化返回 { text, model_string, latency_ms, prompt/completion/total_tokens,
                          reasoning_tokens, finish_reason }
  5. 日志只打：模型串、延迟、token 数、错误码 —— **绝不打密钥、绝不打完整 prompt 正文**
```

### 7.2 必须处理的细节

| 细节 | 要求 |
| --- | --- |
| **前缀未收录** | 若注册表给了 `openai_compat_base`，自动换成 `openai/<裸名>` + 该端点**重试一次**；仍失败则报 `unsupported_provider` |
| **思考 token** | 上游常单列 `reasoning_tokens`，单独记录。它能解释「这么短的输出为什么要 7 秒」 |
| **截断可见** | `finish_reason == "length"` 必须让调用方看见并提示「调大 Max Tokens」，**不许静默丢尾巴** |
| **懒加载** | 接入层首次 import 可能有秒级开销，放在调用函数内部，不要放模块顶层 |
| **流式** | 若支持流式：与普通调用共用同一套「前缀兜底 / 错误分级 / 脱敏」；首个增量前失败应可降级为普通调用 |

### 7.3 验证类操作（三个，共用同一返回结构）

| 操作 | 做什么 | 超时 |
| --- | --- | --- |
| 档案级验证 | 用建议模型打一次极短请求（鉴权校验）+ 尽力拉取模型列表 | 短（建议 15s） |
| 模型级验证 | 单模型约 5 token 的补全，证明「密钥 + 模型名」都对 | 短（建议 15s） |
| 保存前验证（草稿） | 收草稿参数，**密钥只在内存里用一次，验证完即弃，不落任何文件** | 短 |

**档案级验证的宽容规则**：如果失败原因是 `model_not_found`，说明**凭据是好的**，只是探测用的模型名不存在 → 视为验证通过。
这条不做，用户会在「密钥没问题但探测模型名过期」时被误判。

## 8. HTTP 接口契约

统一前缀（示例）`/api/llm`。**任何响应都不得包含密钥明文字段。**

| 方法 | 路径 | 说明 | 关键返回 / 错误 |
| --- | --- | --- | --- |
| GET | `/providers` | 服务商目录（协议前缀 + 元信息，**无模型清单**） | `{providers[]}` |
| GET | `/state` | 档案 + 模型 + 默认绑定 + 损坏条目，**一次拉全**（设置页首屏） | `{version, profiles[], models[], default_model_id, skipped_entries[]}`（做了 fallback 才多一个 `fallback_model_id`） |
| GET | `/profiles` | 档案列表 | `{profiles[]}`（无密钥字段） |
| POST | `/profiles` | 新建档案（明文 key 仅在此请求里出现，落盘前加密） | 档案对象；未知服务商 / custom 缺端点 / 名称空 → **400** |
| GET/PUT/DELETE | `/profiles/{id}` | 详情 / 更新 / 删除 | PUT 的 `api_key` **缺省 = 保持现有密钥**；DELETE 级联删其下模型，含默认模型 → **409** |
| POST | `/profiles/{id}/verify` | 验证已存档案（鉴权 + 尽力列模型） | 验证结构；结果持久化到档案 `status` |
| POST | `/profiles/{id}/remote-models` | 拉取上游模型列表（OpenAI 兼容 `GET /models`） | `{profile_id, models[]}`；不支持 → **409 `{manual_only:true, reason}`** |
| POST | `/verify-draft` | **保存前验证**，草稿密钥用后即弃 | 验证结构；带 `model_name` 时验到模型级 |
| GET/POST | `/models` | 模型列表（可 `?profile_id=` 过滤）/ **批量**新建 | `{created[], skipped[{model, reason}]}` —— 重复 / 档案缺失进 `skipped`，**不整批失败** |
| PUT/DELETE | `/models/{id}` | 更新 / 删除 | 删默认模型 → **409** |
| POST | `/models/{id}/verify` | 单模型轻量验证 | 验证结构；持久化到模型 `status` |
| POST | `/models/{id}/activate` | 设为默认模型 | **即时生效**，下一次调用就用新模型，无需重启 |
| PUT | `/settings` | 更新 `default_model_id`（**做了 fallback 才加 `fallback_model_id`**） | 显式传 `null` = 清除；不存在 → 404 |

### 8.1 验证结构（全部验证类端点统一）

```jsonc
{
  "ok": true,
  "error_code": null,                 // 失败时为下面的分级码
  "message": null,                     // 已脱敏、已翻译成中文建议的文案
  "latency_ms": 812,
  "remote_models": ["deepseek-flash", "deepseek-v4-pro"]
}
```

### 8.2 错误分级（对外契约，前端按 code 出建议）

| `error_code` | 判定依据 | 给用户的可执行建议 |
| --- | --- | --- |
| `auth_failed` | 401 / 403 | 检查密钥是否复制完整、是否被撤销/过期、账户是否欠费 |
| `model_not_found` | 404 或错误体含 model | 检查模型名是否正确（含服务商前缀），或从列表重新拉取 |
| `quota_exceeded` | 429 / 余额类 | 账户欠费或触发限流，充值或稍后重试 |
| `timeout` | 超时异常 | 端点不可达或过慢，检查网络/代理，或调大超时 |
| `network_error` | 连接类异常 | 检查网络与代理设置 |
| `provider_error` | 5xx | 上游故障，稍后重试 |
| `unsupported_provider` | 前缀不识别 | 改用「自定义 OpenAI 兼容」端点 |
| `unknown` | 兜底 | 查看日志获取详情 |

**分级判定顺序**（照做，顺序错了会误判）：① 先脱敏 → ② 文本特征（unsupported provider）
→ ③ 异常类名 → ④ HTTP 状态码 → ⑤ 文本兜底（timeout / network / auth）。

**关键前提**：不少上游在 401 时**会把完整密钥回显在错误体里**。
所以「先脱敏再分类」不是洁癖，是防止密钥被写进日志和数据库的唯一时机。

> 这份 `error_code` 集合是**对外契约**：前端、文档、测试都依赖它。加码可以，改码名不行。

## 9. 前端设计

### 9.1 页面结构

设置页新增一个分组（{{设置页入口}}）：

1. **供应商档案卡**：名称、服务商、端点、密钥掩码（`sk-****7f3a` / 「未设置密钥」/「无需密钥」）、
   模型数徽章、最近验证状态与延迟；操作：重新验证、编辑。
2. **模型表**：模型显示名 + `默认` 徽章（做了 fallback 才加 `备用` 徽章）、完整模型串（等宽字体）、
   参数摘要（`temp 0.3 · max 4,096 · 超时 60s`）、逐模型状态、失败原因**内联展示**；
   操作：测试、设为默认、编辑、删除。
3. **数据损坏提示条**（有 `skipped_entries` 时）：`有 N 条旧配置因数据损坏被跳过（…），其余配置不受影响。`
4. **底部说明**：当前默认模型是谁。**没实现自动切换就不要写"失败自动切换"**（见 I7）。

### 9.2 三步向导（核心交互）

```text
[1 选择] 搜索并选择服务商（未列出的 → 自定义 OpenAI 兼容）
   ↓
[2 凭据] 填档案名 / API Key / API Base → **先真实验证**
         验证通过才允许落盘；失败显示「错误标题：可执行建议」，可原地改了重试
   ↓
[3 模型] 拉取上游模型列表勾选 + **手动输入框**（逗号/换行分隔多个）
         参数（temperature / max_tokens / 超时 / 重试）折叠在「模型参数」里
         勾选「保存后设为默认模型」
   ↓
[保存 N 个模型] → 批量提交，部分重复的进 skipped 并提示原因
```

从「添加模型」入口进入时，如果已有档案，**直接跳到第 3 步**。

### 9.3 交互规则（逐条都要实现）

1. **模型名手输是一等公民**，不是兜底。手输与拉取走同一个数据结构和同一个保存路径。
2. **保存前验证**：验证通过才建档案。这一步不能省，否则用户会存一堆错密钥然后逐个试。
3. **密钥编辑留空 = 保持现有密钥**。不要显示明文，也不要显示密文。
4. **凭据变了，旧验证结论作废**：改了 key 或 base，状态重置为「未验证」。
5. **失败可见**：每次验证结果持久化成状态徽章；运行期失败走项目既有的错误通道提示，
   不许「打了条 warning 就当成功」。
6. **拉取模型列表失败不阻断流程**：降级成手输（这本来就是一等路径）。
7. **草稿密钥不进全局状态**：只存在于弹窗组件局部变量里，关闭即丢。
8. **纯逻辑抽出来单测**：模型串组装、手输解析（去重/去非法）、错误码→文案、
   状态→色 tone、延迟格式化。这些不需要跑浏览器就能测。

## 10. 安全（不可打折）

| 项 | 策略 |
| --- | --- |
| 落盘 | 密钥**对称加密**存储（如 Fernet），密钥文件与数据文件分开且不进版本库 |
| 接口 | 任何响应不含密钥明文/**密文**；`GET` 只返回 `api_key_hint`（尾号）与「已设置」语义 |
| 日志/异常 | 所有对外文案先过统一脱敏函数：① 已知密钥字面量精确替换 → ② `api_key: xxx` / `Authorization: Bearer xxx` 模式 → ③ 裸 `sk-` 前缀 |
| 草稿验证 | 密钥仅在请求内存中使用一次，验证完即弃，不落盘、不进日志 |
| 本地服务 | Ollama 等无密钥档案允许密钥为空，**不要**强行要求填 key |
| 前端 | 密钥输入框 `type="password"`；不使用「回显已保存的密钥」这种交互 |

**自检**：全链路走一遍后，`grep` 整个数据目录与日志文件，确认搜不到密钥明文；确认响应体里没有 `api_key` / `api_key_encrypted` 字段。

## 11. 迁移与兼容

如果项目里已有旧版 LLM 配置（一层结构）：

1. **首次启动自动迁移**：按「服务商 + 解密后 key + 端点」聚合出档案（同 key 多配置只存一份密文），
   每条旧配置生成一个模型条目，旧默认映射到对应模型条目。
2. **可回滚**：迁移后旧文件**改名为 `.v1.bak` 保留**（不删除内容），还原文件名即可回滚。
3. **单条失败只跳过该条**，并在设置页提示「N 条旧配置无法自动迁移」。
4. **解密失败的条目保留原密文** + 标记 `decrypt_failed`，允许重填 key 修复，**不要整条丢弃**。
5. 旧接口：保留**一个过渡版本**（读端点映射为新视图，写端点返回 `410 Gone` 并给引导文案），
   前端切换完成后整体删除。**不允许新旧双写**。

如果项目是**全新**接入（没有旧配置）：跳过本节，但 §5.2 的加载期自愈仍然要做。

## 12. 边界（本提示词最重要的一节）

边界分三个维度，**任何一维越界都算失败**：

| 维度 | 回答的问题 | 对应小节 |
| --- | --- | --- |
| 产品边界 | 这个模块**该做什么**、不该做什么 | §12.1 / §12.2 |
| 改动边界 | 允许**碰哪些文件**、不许碰什么 | §12.3 |
| 完成边界 | **做到什么程度算完**、做不到时怎么降级 | §12.4 / §12.6 |

### 12.0 三条兜底原则（其余条款都可以用这三条推导）

1. **不确定就停，不要替我做决定。** 停下来问一次的成本，远低于做错一整套。
2. **范围外的发现只报告，不实施。** 看到别的模块有问题 → 写进报告，不改代码。
3. **宁可少做，不可留半截。** 没接线的字段、没实现的承诺文案、只跑通一半的流程，
   比"这个功能还没做"危害大得多——因为它看起来是好的。

### 12.1 必须在范围内

- 服务商注册表（协议前缀 + 元信息）。
- 两层数据模型 + 原子持久化 + 逐条容错 + 加载期自愈。
- 网关：超时、重试、错误分级、脱敏、usage 归一化。
- 全部 §8 端点与 §8.1 验证结构。
- 设置页分组 + 三步向导 + 逐条状态展示。
- 密钥加密与全链路脱敏。
- 旧配置迁移（若有）。
- 上述功能的测试。

### 12.2 明确不做（越界即停，先问我）

| 不做 | 理由 |
| --- | --- |
| 聊天/对话界面、Prompt 编辑器 | 这是上层产品功能，不是底座 |
| 多模型智能路由、负载均衡、自动降级链 | 单机场景用不上；静默切换会带来意外费用 |
| 成本/账单/配额面板 | 依赖上游计费口径，各家不一，容易做成假数据 |
| 团队、多租户、用户权限、密钥共享 | 假设变了，是另一套设计 |
| 模型能力评测、benchmark、A/B | 与「接入」无关 |
| 为每家服务商写一个 `provider_xxx.py` | 这正是 P2，要消灭的东西 |
| 把模型清单做成内置下拉 | 这正是 P1，要消灭的东西 |
| 顺手重构别的不相关模块（业务逻辑、UI 主题、构建脚本…） | 违反 §12.3 |

### 12.3 改动范围（硬边界）

1. **只加不改**。新模块放进独立目录，对外只暴露「Store / Gateway / Router 三件套」。
2. 需要改动既有调用点时，**用适配函数包一层**，不改调用方签名，不让调用方感知新模块存在。
3. **不许动**：与 LLM 无关的模块、既有测试的断言、公共组件的 API、构建/打包配置（除非确实缺依赖，且要单独说明）。
4. **不许删**既有功能来"简化"。旧实现要在新实现跑通并验证后才删，且删的时候一并更新文档。
5. 不要为了新模块修改 `.env` / 真实密钥文件；新增变量写进 `.env.example` 并同步配置文档。
6. 提交要按逻辑分组，一个提交只做一件完整的事；不要 `git add -A` 把无关产物带进去。

### 12.4 完成标准（可验证，做不到就是没完成）

| # | 验收项 | 怎么验 |
| --- | --- | --- |
| 1 | **零发版接新模型** | 手输一个上游列表里**没有**的模型名，保存，完成一次真实调用 |
| 2 | **任意 OpenAI 兼容端点可接** | 走「自定义」档案，从新建到调用成功 |
| 3 | **超时生效** | 模拟网络黑洞，请求在配置的超时内失败并给出 `timeout` 建议，不挂起 |
| 4 | **保存前验证** | 填一个错 key，点下一步被拦下并显示可执行建议，**没有任何数据落盘** |
| 5 | **局部损坏不扩散** | 手工改坏一条配置，其余照常加载，界面提示「N 条被跳过」 |
| 6 | **默认模型即时切换** | 切换后下一次调用立即使用新模型，不重启 |
| 7 | **默认模型不可直接删** | 删默认模型返回 409 并引导先改绑 |
| 8 | **安全回归** | `grep` 数据目录与日志无密钥明文；所有响应无密钥字段 |
| 9 | **迁移无损**（若有旧配置） | 升级后模型与默认设置语义等价，可回滚 |
| 10 | **测试全绿** | 新增测试覆盖 §12.1 每条；既有测试不回归；项目规定的检查命令全部通过 |

### 12.5 越界信号（出现任何一条，停下来检查）

- 你在往注册表里写模型名清单 → 违反 I1。
- 你在写 `openai_provider.py`、`deepseek_provider.py` → 违反 P2 的解法。
- 你在某个组件里直接构造 HTTP 客户端调模型 → 违反「唯一出口」。
- 你的响应体里出现了 `api_key` 字段（哪怕是掩码后的完整值） → 违反 I3。
- 你加了一个字段但没有任何代码读它 → 违反 I7。
- 你为了让测试通过而改既有断言 → 违反 §12.3.3。
- 你开始给这个模块加「顺手能做」的第二个功能 → 违反 §12.2。
- 你说「这个我稍后补」而完成了主流程 → 未完成（§12.4 全部通过才算完）。

### 12.6 如果只能做一半，按这个顺序砍

砍的顺序**从后往前**，前面的不许省：

1. 两层模型 + 持久化 + 服务商注册表（**地基，不能省**）
2. 网关（超时 / 重试 / 错误分级 / 脱敏）（**不能省**）
3. 三个验证端点 + 保存前验证（**不能省**，否则配置不可信）
4. 设置页分组 + 逐条状态（可先用最朴素的表单）
5. 三步向导（可先合并成单页表单）
6. 拉取上游模型列表（手输已可用时，这个可以后置）
7. 旧配置迁移（无旧数据则不需要）
8. 备用模型 / fallback（**默认不做**，见 §12.2）

## 13. 常见坑（都在真实项目里踩过）

| 坑 | 现象 | 预防 |
| --- | --- | --- |
| custom 模型的斜杠被误当前缀 | 报 `LLM Provider NOT provided` | custom 恒组装为 `openai/<完整 ID>`，前后端同规则且有测试 |
| 401 回显密钥进日志 | 日志/记录里出现明文 key | 先脱敏再分类；脱敏函数单测覆盖 `Bearer`、`api_key=`、裸 `sk-` |
| SDK 默认超时 600s | 界面挂十分钟 | 网关强制注入，不依赖默认值 |
| 一条坏数据全丢 | 用户「配置全没了」 | 逐条容错 + 界面提示 skipped |
| 界面文案承诺了没实现的行为 | 写着「失败自动切换」但没有切换代码 | I7：没接线就删文案或删字段 |
| 前端组件里直接画模型下拉 | 新模型永远选不到 | 只渲染上游拉取结果 + 手输框，不内置清单 |
| 流式与普通调用两套错误处理 | 流式失败时提示不一致 | 共用同一套分级与脱敏 |
| 测试依赖本机真实密钥 | 换机器测试漂移 | 测试里替换配置源，用假 provider / monkeypatch 网关 |
| 迁移不可回滚 | 升级后发现不对，回不去 | 旧文件改名保留，不删内容 |
| 删除默认模型没拦截 | 运行时「没有可用模型」 | 删除前返回 409，先改绑 |
