### 2.3 `scripts/docker/att.ps1`

`-Action` 取值：`start`（默认）/ `stop` / `status` / `restart` / `logs`；开关：`-Rebuild`、`-NoBuild`、`-WithApp`、`-SkipSettingsFix`、`-ReadyTimeoutSeconds`（默认 600）。

`start` 是 8 步流程（`att.ps1:342-485`）：

1. 检查/生成 `.env`（缺失时从 `.env.example` 复制）、创建 `data/ models/ logs/` 卷目录；
2. 检查流式设置：把 `data/settings.json` 的 `asr_provider` 修正为 `qwen_asr`、`recording_mode` 修正为 `streaming`，**改前自动备份**为 `settings.json.bak-<时间戳>`（`-SkipSettingsFix` 可跳过）；
3. 检查 Docker 守护进程，必要时尝试启动 Docker Desktop（最多等 240s）；
4. 检查 `ATT_BACKEND_PORT`（默认 8000）占用：若被本项目容器占用则走复用，否则报错并提示改 `.env`；
5. 准备 `att-runtime:local` 镜像（存在即跳过，`-Rebuild` 强制重建，构建失败自动重试一次）；
6. `docker compose up -d`，等待 `att-asr` 健康检查通过（180s）；
7. 容器内校验 GPU（`torch.cuda.is_available()` + `nvidia-smi`）；
8. 触发 `/api/preload` 预热，轮询 `/api/health` 直到 `ready && loaded`（默认上限 600s）。

`-WithApp` 会在启动完成后设置 `ATT_REQUIRE_EXISTING_BACKEND=1`、`ATT_BACKEND_PORT=<端口>` 并执行 `npm run electron:dev:existing-backend`（`att.ps1:476-485`）。

## 3. 测试

### 3.1 后端（pytest）

```bash
uv run python -m pytest tests -q
```

**实测收集数量：278 个用例**（`uv run python -m pytest tests -q --collect-only` → `278 tests collected in 2.48s`）。`pyproject.toml` 的 `[tool.pytest.ini_options]` 设了 `testpaths = ["tests"]`，因此不带路径也只收集 `tests/`。

测试文件：`tests/*.py` 共 **27 个**（其中 26 个用例文件 + `conftest.py`）。

**测试隔离约定**（`tests/conftest.py`）：

- `isolate_factory_user_settings` 是 **autouse** fixture（`conftest.py:31-46`），把 `app.stt.factory.user_settings` 猴子补丁成 `get_all()` 返回 `{}` 的空实现。
- 原因：`app.stt.factory` 在 import 期就绑定了 `app.config.user_settings`，而 `get_asr_provider_config()` 会把用户设置合并进运行时配置，且豆包密钥优先级是「用户设置（密文）> runtime 参数 > 环境变量」。本机一旦在设置页保存过 Token，断言就会随环境漂移。
- 新增涉及 `get_asr_provider_config()` 的用例**不要移除这个 fixture**。
- 另有 `temp_dir`（`tests/.tmp/<uuid>`，用例结束删除）与 `sample_audio`（1 秒静音 wav）两个普通 fixture。

### 3.2 前端（Node）

```bash
node scripts/run-node-tests.mjs          # 全部
node scripts/run-node-tests.mjs overlay  # 文件名子串过滤
NODE_TEST_TIMEOUT_MS=60000 node scripts/run-node-tests.mjs
```

**为什么不能直接用 `node --test`**（`scripts/run-node-tests.mjs:2-8` 原文）：

> 背景：tests/ 下有两个手写 main() 的用例脚本（test_unified_overlay_manager.js、test_selection_toolbar_manager.js）会在结束时主动调用 `process.exit(0)`，直接使用 `node --test tests/*.js` 会被它们提前截断测试收集与汇总输出。因此这里改为「逐个文件串行 spawn 一个 node 进程」，最后一个文件跑完再统一汇总，只要有任一文件失败就以非 0 退出码结束。

执行器行为：枚举 `tests/*.js|*.mjs` 按文件名排序（`run-node-tests.mjs:36-53`），逐个 `spawn(process.execPath, [file])` 且 `stdio: 'inherit'`（`:59-66`），单文件超时默认 120s（`:26`），汇总按**文件**计 PASS/FAIL（`:154-171`）。

**实测文件数：15 个**（`ls tests/*.mjs tests/*.js | wc -l`）。注意 `test_selection_toolbar_manager.js` 已不存在于当前 `tests/`，注释里仍提到它。

### 5.2 `housekeeping.py` 的四类扫描

`app/repositories/housekeeping.py` 定义四类问题（`housekeeping.py:36-44` 文档、`:70-84` 常量）：

| 类别 | 标签 | 判定条件 | 清理动作 |
| --- | --- | --- | --- |
| `orphan_image` | 孤儿图片 | `data/clipboard/images/` 中未被任何剪贴板条目引用，且文件年龄 ≥ `orphan_min_age_hours`（默认 **1.0h**，防与捕获流程竞态） | 删除文件 |
| `stale_segment` | 残留片段音频 | 会话已完成且合并音频已落盘，片段音频仍在磁盘 | 删除文件 + 清记录里的音频路径 |
| `stuck_session` | 卡死会话 | 创建时间（或文件 mtime）超过 `stuck_after_hours`（默认 **6.0h**）仍停在 `recording` | 标记为 `failed` |
| `stuck_record` | 卡在中间态的记录 | 超过 6.0h 仍停在 `optimizing` / `transcribing` | 标记为 `failed` |

安全约定：默认 `dry_run=True` 只扫描；只有显式 `dry_run=False` 或 `ATT_HOUSEKEEPING_APPLY=1` 才真正删除/改状态；所有删除先经 `is_within_directory` 校验，越界跳过并记录；状态改写走 `write_json_atomic_async` + 资源锁。

**启动期只做 dry-run**：`app/main.py:99-101` 调用 `run_startup_housekeeping(settings.data_path)`，而该函数刻意不接受 `dry_run` 参数、也不读环境变量，内部固定 `report.dry_run = True`（`housekeeping.py:804-819`）。破坏性清理只能由 CLI 显式触发。

## 6. 打包

### 6.1 `node scripts/package-electron.js --win` 流程

`scripts/package-electron.js` 的 `main()`（`:312-334`）：

1. 校验 `uv` 与 `npm` 在 PATH 中（`:313-319`）。
2. `prepareBundledPython()`（`:225-259`）：按 `.python-version`（或 `--python-version=`）解析 uv 托管的 Python（缺失则 `uv python install`），把整个解释器目录 `cpSync` 到 `python-dist/`，删掉 `Lib/EXTERNALLY-MANAGED`，再执行
   `uv pip install --python python-dist/python.exe --link-mode copy --compile-bytecode -r pyproject.toml`。
3. `npm run build`（渲染进程）。
4. `npx electron-builder <targetArgs>`；`--win`/`--mac`/`--linux` 选择平台，额外支持 `--nsis` / `--portable` 只重跑单个目标（`:144-157`）。
5. `verifyPackagedResources()`（`:267-310`）。
6. 打印「Output is in release/」。失败统一 `console.error('[package] ...')` + `exit(1)`（`:336-339`）。

### 6.2 `electron-builder.yml`

`files`（打进 asar，只放代码）：

```
dist/**/*
electron/**/*
app/**/*.py
package.json
```

`extraResources`（解包到 `resources/`）：

| from | to | filter |
| --- | --- | --- |
| `python-dist` | `python` | `**/*` |
| `app` | `app` | `**/*.py` |
| `prompts` | `prompts` | `**/*.txt` |

其它：`directories.output: release`、`win.target: [nsis, portable]`、`nsis.oneClick: false` / `allowToChangeInstallationDirectory: true`、`mac.target: [dmg, zip]`。注释明确要求 `data/`（含 `.encryption_key`）与 `models/` **绝不能**进包。

### 6.3 `verifyPackagedResources()` 校验了什么

硬闸门，任一不满足即抛错（`package-electron.js:267-310`）：① `release/win-unpacked` 必须存在；② `resources/data`、`resources/models` **必须不存在**（否则等于把解密密钥与密文一起分发）；③ `resources/app/main.py` 必须存在（后端源码随包）；④ `resources/prompts/` 下至少有 1 个 `.txt` 预设（否则打包版提示词预设为 0 个、LLM 优化失效）；⑤ `resources/python/python.exe`（或 POSIX 的 `bin/python3`）必须存在。通过后打印预设数量。

### 6.4 当前打包状态（实测）

**`--win` 在 nsis 阶段失败。**

- 证据 1：`tmp/package-nsis-retry.log:163` → `[package] npx electron-builder --win nsis exited with code 4294967295`（即 `-1`）；其上两行是 `• building target=nsis file=release\Audio to Text Setup 1.0.0.exe archs=x64 oneClick=false perMachine=false`（`:162`）。同一次运行中 `vite build` 与 `win-unpacked` 解包均成功（`:158-161`）。
- 证据 2：`release/` 下只有 `builder-debug.yml` 与 `win-unpacked/`，**没有任何安装包**（无 `Audio to Text Setup 1.0.0.exe`）。
- 结论：当前只能得到 `win-unpacked` 免安装目录，`nsis` 安装器产不出来；`win.target` 需要收敛为 `portable`，或先裁剪 `python-dist` 载荷。

**`extraResources` 未包含 `scripts/`。** 实测 `release/win-unpacked/resources/` 下只有 `app`、`prompts`、`python`（外加 `app.asar`、`elevate.exe`、`app-update.yml`）。而后端在本地桥接模式下会 spawn：

```python
sys.executable, "-m", "uvicorn", "scripts.qwen_streaming_service:app", "--host", ..., "--port", ...
```

（`app/services/qwen_streaming_service_manager.py:162-173`，`cwd` 设为项目根 `parents[2]`）。打包后 `scripts/` 不在 `resources/` 里，**本地流式桥接在打包版无法启动**；只有配 `QWEN_STREAMING_BASE_URL` 走远端桥接时才绕开这个问题。

## 7. Docker

### 7.1 `docker-compose.yml` 服务划分

`name: att`，两个服务共用镜像 `att-runtime:local`（构建配置只挂在 `asr` 上，避免并发构建同一目标）：

| 服务 | 容器名 | 端口 | 关键环境变量 | 依赖 |
| --- | --- | --- | --- | --- |
| `asr` | `att-asr` | **不发布到宿主**（仅容器网络内 `:9000`） | `QWEN_STREAMING_*`、`HF_HUB_OFFLINE=1`、`QWEN_STREAMING_AUTO_PRELOAD=1` | — |
| `backend` | `att-backend` | `127.0.0.1:${ATT_BACKEND_PORT:-8000}:8000` | `DATA_DIR=/app/data`、`ASR_PROVIDER=qwen_asr`、`QWEN_STREAMING_BACKEND=remote_bridge`、`QWEN_STREAMING_BASE_URL=http://asr:9000`、`QWEN_ASR_DEVICE=cpu` | `asr` 需 `service_healthy` |

卷（两服务共用）：`./data:/app/data`、`./models:/app/models`、`./logs:/app/logs`、`./.env:/app/.env:ro`。

其它：`asr` 设 `shm_size: 8gb`、`gpus: all`，健康检查打 `http://127.0.0.1:9000/api/health`（5s 间隔 / 30 次重试 / 30s 启动宽限）；`backend` 健康检查打 `:8000/api/health`（10s 间隔 / 12 次）。

### 7.2 镜像与入口

`docker/Dockerfile`：基础镜像 `vllm/vllm-openai:v0.14.0`（与 `qwen-asr` 锁定的 `vllm==0.14.0` 对应，CUDA 13 覆盖 RTX 5090）；装 `ffmpeg / libsndfile1 / libnuma1 / sox / curl`；用 `uv export --no-emit-project --frozen --no-dev` 从锁文件导出依赖再 `uv pip install --system`；只拷 `app/`、`scripts/`、`prompts/`；**清空基础镜像的 `ENTRYPOINT`**（否则 compose 的 command 会被拼成 `vllm serve python3 -m uvicorn ...`）。

`scripts/docker/asr_entrypoint.sh`：后台起 `uvicorn scripts.qwen_streaming_service:app`，`trap` 转发 TERM/INT；若 `QWEN_STREAMING_AUTO_PRELOAD != 0`，先轮询 `/api/health`（最多 60 次 × 2s），再 `POST /api/preload`（最长 900s），最后 `wait`。自动预热是为了避免「容器被自动重启 → 模型未加载 → 前端显示模型加载中并禁用按钮 → 用户死局」。

### 7.3 后端与容器共用 `data/` 的单写者约束

compose 把宿主 `./data` 直接挂进容器（`docker-compose.yml:30`），因此**容器后端与原生后端会争抢同一份 `data/`**。`app/main.py:84` 在启动时 `acquire_writer_lock()`，第二个写者会收到中文 `RuntimeError` 并拒绝启动：

> 检测到另一个 ATT 后端进程正在写同一份数据目录，已拒绝启动：pid=…、host=…、started_at=…、heartbeat_at=…。JSON 文件存储不支持多进程同时写入（会静默丢数据），请先关闭另一个后端进程（Docker 容器或原生应用），或设置环境变量 `ATT_ALLOW_MULTI_WRITER=1` 显式允许多写者。

（原文见 `app/repositories/writer_lock.py:368-374`。）

因此正确用法是二选一：

- **容器模式**：`att-start.bat`（或 `att-start-app.bat`）启动容器，再用 `npm run electron:dev:existing-backend` 让 Electron 复用容器后端（`att.ps1:474-484` 已自动设置环境变量）。
- **原生模式**：不启容器，直接 `npm run electron:dev`，由 Electron 自己拉后端。

`ATT_ALLOW_MULTI_WRITER=1` 只是迁移/调试用的旁路，会真的丢数据。

## 8. 排障手册

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 后端起不来，报「检测到另一个 ATT 后端进程正在写同一份数据目录，已拒绝启动」 | `data/.writer.lock` 被另一个后端/容器持有 | 关掉另一个后端或 `att-stop.bat` 停容器；确认无残留进程后重试。仅迁移/调试可临时 `ATT_ALLOW_MULTI_WRITER=1`（有丢数据风险）。锁的陈旧接管条件是心跳 >60s 或同机 PID 不存在（`writer_lock.py:29, 356-366`） |
| 端口被占 | `npm run backend:dev:uv` / uvicorn 直接起在 8000 时端口冲突；docker 场景 `ATT_BACKEND_PORT` 被别的进程占用 | Electron 路径会自动向后找可用端口（`manager.js:207-215`），无需处理；docker 场景按提示改 `.env` 的 `ATT_BACKEND_PORT`（`att.ps1:377`）。`npm run dev` 用 `--strictPort`，8090 被占会直接失败 |
| 「请先开启模型」/「模型加载中」按钮点不动 | 本地 provider 未 `warmup()`，或桥接服务未就绪 | 点「开启模型」→ `POST /api/model-service/start`；容器场景先跑 `att-start.bat`（第 8 步会预热）。若 `loading=true` 但实际没在加载，属于远端桥接的已知坑（`streaming_bridge_target.py:132-136`） |
| 流式不可用（「当前环境暂不支持流式」） | Windows 本地后端不支持 Qwen 流式（`qwen_asr_provider.py:113-122`）；或 `recording_mode` 不是 `streaming`；或 provider 不是 `qwen_asr`/`doubao_asr` | 走远端桥接（`QWEN_STREAMING_BASE_URL`，容器场景由 compose 注入 `http://asr:9000`），或本地 `npm run qwen:streaming:uv`；也可换豆包在线 provider。检查 `data/settings.json` 的 `asr_provider` 与 `recording_mode` |
| 豆包流式提示缺凭据 | Access Token 未配置 | 设置页填 Token（加密落盘为 `doubao_asr_api_key_encrypted`），或设 `DOUBAO_ASR_API_KEY`；`GET /api/settings` 只回报 `doubao_asr_api_key_set: bool` |
| 麦克风权限被拒 / 录音无声 | Electron 的权限处理器只放行 `media`（`electron/main.js:140-142`）；系统级麦克风权限未授予 | 在系统设置里授予应用麦克风权限；确认 `setPermissionRequestHandler` 未被改动 |
| LLM 优化返回 502「文本优化失败：…」 | 优化器抛异常（密钥无效、网络不通、模型名错误） | 记录状态已自动复位为 `transcribed` 并写入 `Record.error`，可用设置页「测试连接」定位；注意多 provider 路径**未设请求超时**，服务端无响应时会长时间挂起（`app/llm/providers/openai.py:17-20`） |
| `data/settings.json` 损坏 | 内容非法 JSON / 顶层非对象 / 为空 | `read_json_lenient` 返回默认值，`ensure_dict` 把非对象收敛为空 dict，`UserSettings._load` 回落 `DEFAULT_SETTINGS` 并打 warning（`app/config.py:250-273`）；不会阻塞启动。注意 `att.ps1` 检测到非法 JSON 时会跳过流式设置检查（`att.ps1:308`） |
| 日志在哪 | — | 后端 `logs/app.log`（JSON，5MB×5 轮转）；Electron `logs/electron-overlay.log`；本地流式桥接 `logs/qwen_streaming_service.log`（路径见 `app/services/qwen_streaming_service_manager.py:35`，`stdout/stderr` 重定向见 `:142, 154`）；容器日志用 `att-logs.bat`（`compose logs -f --tail 100`） |
| 打包出来的安装包不存在 | `--win` 的 nsis 阶段失败 | 见 §6.4：改用 `node scripts/package-electron.js --win --portable`，或先收敛 `win.target` |
| 打包版流式用不了 | `extraResources` 缺 `scripts/` | 见 §6.4：补 `electron-builder.yml` 的 `extraResources`，或改用远端桥接 |
| `git clean -xfd` 之后数据全丢 | `data/`、`models/` 在 `.gitignore` 中 | 不要对仓库执行 `git clean -xfd`（`att.ps1` 结尾有同样警示） |
