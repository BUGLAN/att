# 配置说明

本文档由代码提取，来源：`app/config.py`、`.env.example`、`docker-compose.yml`、
`scripts/qwen_streaming_service.py`、`scripts/docker/asr_entrypoint.sh`、
`app/services/settings_service.py`、`app/stt/factory.py`、`app/services/model_service.py`、
`app/utils/encryption.py`。

> 「是否真正生效」一栏以**全仓检索后是否有读取点**为准，不按字段名是否好听判断。

## 0. 配置分三层

| 层 | 载体 | 谁读它 | 何时生效 |
| --- | --- | --- | --- |
| 环境变量层 | `.env` / 进程环境 / `docker-compose.yml` 的 `environment` | `app/config.py` 的 `Settings`（pydantic-settings，`env_file=".env"`） | 进程启动时读取一次（`app/config.py:403-410`） |
| 用户设置层 | `data/settings.json` | `app/config.py` 的 `UserSettings`（模块导入即实例化，`app/config.py:413`） | 每次读写文件；`PUT /api/settings` 写盘 |
| LLM 配置层 | `data/llm_v2.json`（v1 `llm_configs.json` 首次启动自动迁移为 `.v1.bak`） | `app/llm/store.py`（LiteLLM 方案，供应商档案 + 模型条目） | 每次调用 `get_llm_store()`；默认模型切换即时生效 |

`Settings` 的字段与 `UserSettings.DEFAULT_SETTINGS` 键名**刻意保持同名**（如 `asr_provider`、`whisper_model`），
合并规则见 §3。

### 2.3 `hotkey` 结构

## 3. 生效优先级

### 3.1 `data/settings.json` 与 `.env` 谁优先 —— **`settings.json` 优先**

`get_asr_provider_config()` 先铺开全部 `settings.*`（环境变量），最后 `**user_settings.get_all()`（`app/stt/factory.py:32-57`）。
Python 字典展开后写者胜，因此**同名键一律以 `settings.json` 为准**：
`source = { settings.asr_provider, settings.whisper_model, ..., **user_settings.get_all() }` ← 后者覆盖前者。

结论：

| 情形 | 结果 |
| --- | --- |
| 键同时存在于 `.env` 与 `settings.json`（如 `ASR_PROVIDER` / `asr_provider`） | **`settings.json` 胜**。改 `.env` 可能完全不生效 |
| 键只在 `.env` 有（`whisper_compute_type`、`qwen_streaming_backend`、`qwen_streaming_base_url`、`qwen_streaming_timeout_seconds`、`doubao_asr_connect_timeout_seconds`、`doubao_asr_chunk_ms`、`doubao_asr_force_to_speech_time`） | 环境变量胜（无竞争对手） |
| 键只在 `settings.json` 有（`recording_mode`、`silence_*` 等） | `settings.json` 胜 |

`ModelServiceManager` 侧另有一处读取：`_read_bridge_config()` 先取 `settings.qwen_streaming_*`，
再用 `get_asr_provider_config().qwen_asr` 覆盖（`app/services/streaming_bridge_target.py:43-61`），
所以**流式桥接配置同样最终以 `settings.json` 优先**（虽然这三个键目前没有 `settings.json` 默认值）。

### 3.2 豆包 Access Token 的优先级

`resolve_doubao_api_key()`（`app/stt/factory.py:13-27`）的判定顺序：

1. `source["doubao_asr_api_key_encrypted"]`（`settings.json` 里的 Fernet 密文）→ 解密成功即返回；
2. 解密抛异常 → 打 warning，继续往下；
3. `source["doubao_asr_api_key"]`（可能来自调用方显式传入的 `runtime_settings`）；
4. `settings.doubao_asr_api_key`（即 `DOUBAO_ASR_API_KEY` 环境变量）。

即：**用户设置密文 > runtime 显式参数 > `DOUBAO_ASR_API_KEY` 环境变量**。
解密失败**不抛错**，只是回退到环境变量，避免配置损坏导致录音链路完全不可用（`factory.py:16-17` 注释）。

### 3.3 生效时机

环境变量在进程启动时读取一次，改 `.env` 需重启后端。`settings.json` 由 `UserSettings` 在 `app.config`
导入时构造（`app/config.py:413`），此后 `PUT /api/settings` 即时写盘并同步内存；但 provider 只在与
`MODEL_RUNTIME_KEYS` 相关的键**发生变化**时才重建（`settings_service.py:254-259`）。

## 4. 密钥与加密

| 项 | 事实 | 出处 |
| --- | --- | --- |
| 算法 | Fernet 对称加密（`cryptography.fernet.Fernet`） | `app/utils/encryption.py:5, 31` |
| 密钥文件 | `data/.encryption_key`（相对当前工作目录，**不受 `DATA_DIR` 影响**） | `app/utils/encryption.py:29` |
| 密钥生成 | 文件不存在或内容非法时生成新密钥，写入后尽力 `chmod 600`（Windows 不支持则忽略） | `encryption.py:33-70` |
| 密钥轮换 | `rotate_key()` 只换密钥并返回旧密钥，**调用方负责重新加密既有数据**；当前代码库没有调用方 | `encryption.py:108-123` |
| 豆包 Token 落盘 | `data/settings.json` 的 `doubao_asr_api_key_encrypted`；LLM API Key 落盘为 `data/llm_configs.json` 的 `api_key_encrypted` | `settings_service.py:164`、`app/llm/config_manager.py:105, 115, 149` |
| 加密实例 | 全局单例 `get_encryption()`（`_encryption`） | `encryption.py:126-135` |
| 解密失败行为 | LLM：`decrypt_key()` 记 error 后返回 `None`；豆包：记 warning 后回退环境变量，不抛错 | `config_manager.py:221-226`、`factory.py:19-27` |

**脱敏契约（`GET /api/settings`）**：响应里既没有明文 `doubao_asr_api_key`，也没有密文
`doubao_asr_api_key_encrypted`，只有一个布尔 `doubao_asr_api_key_set`（`settings_service.py:133-145, 196`）。
`PUT /api/settings` 的响应同样走 `mask_doubao_secret()`（`settings_service.py:294`）。

**明文不落盘的保证**：`_apply_doubao_secret_update()` 会先 `pop` 掉 `doubao_asr_api_key` 与
`doubao_asr_api_key_clear`，再写入密文键（`settings_service.py:157-168`），因此明文键永远不会进 `settings.json`。

**LLM 侧脱敏**：`GET /api/llm/configs` 与 `GET /api/llm/configs/{id}` 的响应体不含 `api_key`
（`app/api/routers/llm.py:55, 82` 注释「api_key is NOT returned for security」）。

> ⚠️ 密钥文件与 `data/` 一起备份/迁移。`data/.encryption_key` 丢失会导致既有密文**无法解密**，
> 豆包 Token 会静默回退到环境变量，LLM 配置则直接不可用。
