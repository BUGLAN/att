# 豆包在线 ASR 接入（火山引擎 · 双向流式）

> 目标：在「流式录音」这条链路上接入火山引擎豆包双向流式语音识别（bigmodel / SAUC 二进制协议），
> 让用户不依赖本地 GPU 也能拿到实时转写；同时保持 Whisper / Qwen 两条既有链路零改动。
> 协议事实来源：`E:\repo\notes\Agent 产出\火山豆包双向流式 ASR 调用文档.md` +
> 火山官方文档 <https://docs.volcengine.com/docs/6561/1354869>（双向流式 WebSocket）。

## 一、结论速览

| 项 | 值 |
| --- | --- |
| provider 名 | `doubao_asr`（`ASRProviderType.DOUBAO_ASR`） |
| 接入点 | `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel` |
| 鉴权 | 握手头 `X-Api-Key` + `X-Api-Resource-Id` + `X-Api-Connect-Id`（都不是 URL 参数） |
| 资源 ID | 默认 `volc.seedasr.sauc.duration`（ASR 2.0）；1.0 账号用 `volc.bigasr.sauc.*` |
| 音频 | PCM / 16 kHz / 单声道 / 16 bit，200 ms 一包（6400 字节） |
| 传输帧 | 4 字节头 + `[序号 int32?]` + `payload_size uint32 BE` + payload |
| 关键参数 | `result_type: 'full'` + `show_utterances: true` |
| 文本判据 | `utterances` 的 **definite 连续前缀**，不是 `result.text` 变化 |
| 本地模型 | 不需要（`model_service_mode = online`，凭据配齐即为就绪） |
| 依赖 | 仅用现有 `websockets>=12` 的同步客户端（`websockets.sync`），**未新增任何依赖** |

## 三、密钥流转（硬约束）

```
设置页输入（明文，只存在于表单内存）
  → PUT /api/settings  { doubao_asr_api_key: "..." }
  → settings_service 加密 → data/settings.json: doubao_asr_api_key_encrypted
  → GET /api/settings 只返回 doubao_asr_api_key_set: true/false（明文与密文都不回传）
  → factory 解密 → 只用于构造握手头（不进日志、不进异常文案）
```

- 空串 = 「本次不修改」：桌面端保存会整份提交快照，不能因为表单为空就把密钥清掉；
- 清除必须显式 `doubao_asr_api_key_clear: true`；
- 环境变量 `DOUBAO_ASR_API_KEY` 作为兜底（加密设置优先）。

## 四、与调用文档的两处差异（都按官方协议实现）

1. **错误帧布局**：调用文档记成「4 字节头 + 序列化/压缩标志字节 + 错误码 + 长度 + 信息」，
   官方协议与 Python/Go 的 sauc demo 都是「4 字节头 + 错误码 uint32 + 信息长度 uint32 + 信息」。
   本实现按官方布局解析，并保留「多一个字节」形态的容错
   （见 `_parse_error_frame`，两种布局都试，取长度吻合且错误码合理的那种）。
2. **末包 flags**：官方 demo 有 `0b0010`（末包无序号）与 `0b0011`（末包负序号）两种写法。
   本实现全程不发序号，因此末包用 `0b0010`，与调用文档 §4.2 一致。

## 五、推流与收尾节奏

- 前端 worklet 每 200 ms 送一包 3200 采样，后端再按 200 ms 切帧（与前端节奏对齐，多余部分缓存）；
- 每包推完等待服务端结果（默认 `drain_timeout = 0.1s`），把「已确认句 + 未定稿尾巴」作为整场文本回给前端
  （前端 `stream_partial` 是覆盖式更新，所以必须回整场文本）；
- `finish()` 发末包后等「末包标记 / 连接关闭 / 静默 1.2s」三者之一，硬超时 6s，避免停止录音时长时间卡住；
- 批量转写（单段/多段模式）复用同一条会话：快速推流 + 每 25 包清一次接收队列，防止反向背压。

## 六、错误归一化

三类来源统一成 `SaucSessionError`（带 `kind / retryable / next_action / provider_code`），
文案直接给用户「去修复」还是「立即重试」：

| 来源 | 例子 |
| --- | --- |
| 服务端错误帧 | `45000001` → protocol/不可重试；`45000081` → network/可重试；`55000031` → quota |
| 握手 HTTP 状态 | `401` → auth（Token 无效）；`403` → auth（Resource ID 与开通产品不匹配，文案直接给出 1.0/2.0 规律） |
| WebSocket 关闭码 | `1002/1007/1008/4400-4499` → protocol/不重试；`1011-1013` → server/重试；其余 → network/重试 |

> 反直觉但必须：服务端拒绝请求时常常**不发错误帧直接断连**，若一律归成 network 就会把
> 「请求被拒」当「网络抖动」反复重试。

## 七、验证方式

### 1. 真实凭据探针（推荐先跑这个）

```powershell
$env:DOUBAO_ASR_API_KEY = "<火山语音技术 Access Token>"
uv run python scripts/probe_doubao_asr.py --wav tmp-audio/sample.wav
uv run python scripts/probe_doubao_asr.py --wav x.wav --fast          # 无间隔快速推送
$env:DOUBAO_ASR_RESOURCE_ID = "volc.bigasr.sauc.duration"             # 换 ASR 1.0
```

脚本复用 App 内同一套 provider 代码，输出握手 log id、逐帧文本、6 条判据与退出码。
注意「首句回显 ≤ 2s」按**首个中间结果**算，不是最终确认（最终确认必然要等端点静音判定）。

### 2. 单测（无需凭据）

```bash
uv run python -m pytest tests/test_volcengine_sauc.py tests/test_doubao_asr_provider.py \
  tests/test_doubao_settings.py tests/test_doubao_wiring.py -q
node scripts/run-node-tests.mjs      # streamProtocol 的 provider 判定
```

| 测试文件 | 锁死的点 |
| --- | --- |
| `tests/test_volcengine_sauc.py` | 帧头位域、gzip 往返、错误帧两种布局、unknown 容错、definite 前缀推进、三类错误归一化 |
| `tests/test_doubao_asr_provider.py` | 握手头、200ms 切帧、末包 flags、整场文本累计、错误帧/断连抛出、finish 收尾、批量转写 |

## 八、已知边界 / 未验证项

- **未用真实凭据跑通识别**（本次没有可用 Token）：已实测的是握手路径 —— 用无效 Token 访问真实接入点，
  服务端返回 `401 Unauthorized`，本实现正确归一化为「鉴权失败：Access Token 无效或已过期」。
  识别质量、首句延迟、计费时长一致性需要用户用自己的凭据跑 §7.1 的探针确认。
- 服务端静音关会话（VAD，约 30s+）目前按「network/可重试」报错，**没有做自动重连与断点补传**
  （Qwen 链路也没有；要做得单独设计，见调用文档 §9）。
- 前端流式录音不做静音自动暂停，也没有暂停期保活帧；长时间静默由服务端关会话后由用户重开。
- 未接热词（`corpus.hotwords`）与 `enable_ddc`（语义顺滑）开关，只接了对话上下文（续录偏置）。
